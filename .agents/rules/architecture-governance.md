# قواعد الحوكمة والمعمارية العامة (Architecture & Governance)

> المرجع الأعلى: [`AGENTS.md`](../../AGENTS.md) (الدستور) · خريطة التوثيق: [`docs/DOCUMENTATION_MAP.md`](../../docs/DOCUMENTATION_MAP.md) · تتبع الميزات: [`docs/features-tracker.md`](../../docs/features-tracker.md)

## 1. بروتوكول منع الهلوسة (Zero-Hallucination Protocol)
1. **لا تخمن أبداً:** لا تفترض وجود دالة أو متغير أو ملف. تحقق بأدوات البحث (`grep` أو البحث في المستودع) قبل أي تعديل.
2. **استخدم الموجود:** النظام يمتلك مكونات واجهة وأدوات خلفية جاهزة — ابحث عنها قبل بناء بديل جديد (انظر [`/skills/beidar-architecture-navigator/SKILL.md`](../skills/beidar-architecture-navigator/SKILL.md)).
3. **التعديلات الجراحية فقط:** عدّل الجزء المطلوب حصراً. يُمنع حذف تعليقات أو دوال أو إعادة كتابة ملف كامل ما لم يُطلب صراحة.
4. **تحقق من الواردات:** Go يفشل في البناء عند وجود `import` غير مستخدم — نظّف الواردات بعد كل تعديل.
5. **شغّل الاختبارات:** بعد أي تعديل خلفي شغّل `go test ./internal/... ./pkg/...` (وأضف `-race` للمسارات الحساسة)، وبعد أي تعديل واجهة شغّل `npm run typecheck` من `frontend` ثم `npx vitest run --fileParallelism=false`.
6. **طريقة البناء الوحيدة:** يُمنع تشغيل `wails build` أو `npm run build` مباشرة. البناء حصراً عبر `pwsh ./scripts/build.ps1`، ولا تبنِ إلا بطلب صريح من المستخدم.

## 2. الأولوية الحاكمة (Priority Invariant)
الأولوية القصوى دائماً هي **تحسين وتطوير الميزات الحالية** ورفع كفاءتها ومتانتها الأمنية. يُمنع الانجرار إلى هندسة زائدة (Over-engineering) أو استبدال أنظمة قائمة تعمل.

## 3. سيادة المصدر الواحد وصيانة المراجع (Single Source of Truth)
- **لكل قاعدة موقع واحد:** القواعد الحاكمة العامة في `AGENTS.md` الجذر، وقواعد النطاقات في `.agents/rules/*.md`، والتفاصيل الموسعة في `.agents/skills/*/SKILL.md`، وخطط التوثيق في `docs/DOCUMENTATION_MAP.md`. يُمنع إعادة صياغة قاعدة موجودة في مكان آخر؛ بل أحِل إليها بالمسار.
- **صيانة المراجع:** أي ملف أو مسار مذكور في التعليمات يجب أن يكون موجوداً فعلياً. عند حذف أو نقل ملف مذكور، حدّث كل الإشارات إليه في نفس الجلسة (`git grep`).
  - مثال واقعي: كان الدستور يشير إلى مصفوفة `allMigrations` وهي غير موجودة؛ الاسم الفعلي في [`internal/repository/migration.go`](../../internal/repository/migration.go) هو `registeredMigrations`.
- **التوثيق التاريخي إلحاقي فقط:** `CHANGELOG.md` وتقارير المراجعة وسجل الجلسات — تُضاف تصحيحات مؤرخة ولا يُحذف أو يُعاد كتابة التاريخ.

## 4. حظر ازدواجية القدرات بلا مبرر (No Unjustified Duplication)
- أي قدرة منفذة مرتين بلا مبرر واقعي تُعد عيباً تصميمياً. المبررات المقبولة حصراً: اختلاف المنصة (`*_windows.go` مقابل `*_other.go`)، اختلاف زمن التشغيل (متصفح مقابل Go)، عقود الاختبار (Mock مقابل تنفيذ)، أو قيود أداء مثبتة بالقياس.
- عند اكتشاف ازدواجية: يُفضَّل التوحيد في مصدر واحد يُستورد منه، أو توثيق المبرر في موضع الكود.

## 5. بوابة التوثيق الإلزامية (Documentation Sync Gate)
- **قبل بدء أي عمل:** اقرأ `docs/DOCUMENTATION_MAP.md` وحدّد المستندات المتأثرة وفق مصفوفة المزامنة، وأعلنها في أول رد.
- **قبل الكومت:** حدّث `CHANGELOG.md` تحت `[Unreleased]`، ثم شغّل:
  ```bash
  node scripts/docs-gate.mjs --strict-refs
  ```
- **قبل الدفع:** `node scripts/docs-gate.mjs --push` (يُفرض عبر `frontend/.husky/pre-push` وخطوة `Documentation Gate` في CI).
- **لا رقم من الذاكرة:** كل رقم في أي مستند يأتي من أمر قابل للتشغيل مذكور بجانبه. الأرقام المرجعية تعيش في بلوك `docs-metrics` داخل خريطة التوثيق.
- مفتاح الطوارئ الوحيد: `BEIDAR_DOCS_GATE=off` ويجب تبريره في رسالة الكومت.

## 6. العمليات على Git
- لا `commit` ولا `push` إلا بطلب صريح من المالك.
- لا تعمل مباشرة على فرع مشترك عند تغييرات بنيوية كبرى إلا بعزل العمل في فرع/`git worktree` مستقل.
