## 3. البوابات الثلاث (Mandatory Gates)

### 🚪 البوابة 1 — قبل بدء العمل (Pre-Work)
1. اقرأ [`AGENTS.md`](../AGENTS.md) ثم هذا الملف، ثم قاعدة النطاق والمهارة المعنية في `.agents/`.
2. اقرأ [`docs/features-tracker.md`](features-tracker.md) (ما أُنجز / الفجوات / القرارات المحمية).
3. **حدّد مسبقاً** المستندات التي سيتغيرها العمل (وفق مصفوفة القسم 2) وأعلنها في بداية المهمة.
4. لا رقم ولا مسار ولا اسم ملف من الذاكرة — تحقق بالبحث أو بالأمر.
5. إن كان العمل سينقض قراراً محمياً موثقاً في المتتبع ⇒ اطلب موافقة صريحة أولاً.

### 🚪 البوابة 2 — قبل الكومت (Pre-Commit)

| # | الفحص | الأداة | الحالة عند الفشل |
|---|---|---|---|
| 1 | انحراف الأرقام المرجعية (Vitest/E2E/Go/مستندات) | `node scripts/docs-gate.mjs` | ⛔ **يوقف الكومت** |
| 2 | تغطية الجرد (لا مستند غير مسجل) | نفس الأمر | ⛔ **يوقف الكومت** |
| 3 | كومت كود بلا أي تحديث توثيق مرافق | نفس الأمر | ⛔ **يوقف الكومت** |
| 4 | سلامة مراجع المسارات في `AGENTS.md` و`.agents/` | `--strict-refs` | ⛔ مع العلم · ⚠️ تحذير بدونه |
| 5 | **تأكيدات الكود** (ثوابت مُثبَّتة نصياً: WAL، قفل الاتصال، تقريب الأقساط، تعقيم CSV، Tarpitting، تسلسل الطباعة...) | نفس الأمر | ⛔ **يوقف الكومت** |
| 6 | `CHANGELOG.md` محدَّث تحت `[Unreleased]` | يدوي (قاعدة) | ⛔ يوقف المراجعة |
| 7 | تنسيق واختبارات الملفات المُجهَّزة | `frontend/.husky/pre-commit` → `lint-staged` | ⛔ **يوقف الكومت** |

> **فحص 5 — ما هو:** كل ثابت معماري أو عيب مُصلح يُثبَّت بدليل نصي في مصفوفة `CODE_ASSERTIONS` داخل [`scripts/docs-gate.mjs`](../scripts/docs-gate.mjs) بثلاثة أنماط: `mustContain` (الدليل باقٍ) · `mustNotContain` (العبارة الممنوعة لم تعد) · `count` (تكرار محدد بالضبط).
> **لماذا:** بدونه يمكن أن يعود عيب مُغلق إلى الكود بينما يبقى التوثيق يقول «مُصلح» — انحراف صامت.
> **عند الفشل:** إما الكود انحرف (أصلحه/أضف تصحيحاً مؤرخاً) — **لا تُحذف التأكيد ولا تُضعِفه بصمت**.

### 🚪 البوابة 3 — قبل الدفع إلى GitHub (Pre-Push)
```bash
node scripts/docs-gate.mjs --push      # يفحص مدى كل الكومتات غير المدفوعة
```
- يمنع الدفع إذا احتوى أي كومت غير مدفوع تغييرات كود بلا توثيق مرافق.
- **CI خط الدفاع الأخير:** وظيفة `docs-gate` في [`.github/workflows/ci.yml`](../.github/workflows/ci.yml) تفشل عند انحراف الأرقام أو الجرد.
- **سقّاطة التغطية (Coverage Ratchet):** وظيفة `go-backend` تشغّل مجموعة الاختبارات بقياس شامل (`-covermode=atomic -coverpkg=... -coverprofile=coverage.out`)، تطبع جدول التغطية في ملخص التشغيل، ترفع `coverage.out` كأرتيفاكت `go-coverage`، وتمنع التراجع عبر خطوة `node scripts/coverage-gate.mjs --profile=coverage.out --min=<العتبة>`. التعريف والخارج عن المقام في [`docs/testing.md`](testing.md).

## 4. الأرقام المرجعية (Baseline Metrics)

**القاعدة الحاكمة:** كل رقم مكتوب في أي مستند يأتي من أمر قابل للتشغيل ويُذكر معه الأمر. **يُمنع** كتابة رقم من الذاكرة أو من تقرير قديم.

البلوك التالي يُتحقق منه آلياً بواسطة [`scripts/docs-gate.mjs`](../scripts/docs-gate.mjs) (عدّ ملفات فعلي — سريع وحتمي):

```docs-metrics
vitest_test_files=36
e2e_spec_files=18
go_test_files=129
docs_files=14
```

الأرقام التي تحتاج تشغيل اختبارات لا تُوضع في البلوك الآلي، بل في الجدول التالي وتُحدَّث عند تغيّرها:

| الرقم | القيمة (تحقق: 2026-10-05) | أمر التحقق |
|---|---|---|
| ملفات اختبار Vitest | 36 ملفاً في `frontend/src/**/*.{test,spec}.ts(x)` | `find frontend/src -name '*.test.*' -o -name '*.spec.*' \| wc -l` |
| ملفات مواصفات E2E | 18 ملفاً في `frontend/e2e/*.spec.ts` | `find frontend/e2e -name '*.spec.ts' \| wc -l` |
| ملفات اختبار Go | 129 ملفاً في `internal/` و`pkg/` | `find internal pkg -name '*_test.go' \| wc -l` |
| مهاجرات Supabase | 1 ملف في `supabase/migrations/` | `ls supabase/migrations/ \| wc -l` |
| مهاجرات SQLite المرقمة | مصفوفة `registeredMigrations` في `internal/repository/migration.go` | `grep -c "Version:" internal/repository/migration.go` |
| عدد حالات الاختبار الفعلي | يُقاس بتشغيل المجموعات، ويُذكر مع تاريخ التحقق | `npm run test:ci` · `npx playwright test --list` |

> ℹ️ أي رقم في `README.md` أو غيره لا يطابق هذا القسم يُعد انحرافاً يجب تصحيحه.

## 5. قواعد الانحراف (Drift Rules) — إلزامية

1. **لا ادعاء بلا دليل:** كل جملة تقنية تُسند إلى `ملف:سطر` أو نتيجة أمر مُشغَّل، لا إلى الذاكرة.
2. **التوثيق التاريخي مُلحَق فقط:** `CHANGELOG.md` و`docs/REMEDIATION_HANDOFF_2026-08-13.md` — تُضاف تصحيحات مؤرخة ويُمنع حذف أو إعادة كتابة التاريخ.
3. **عند حذف/نقل أي ملف:** ابحث عن كل مرجع له (`git grep`) وحدّثه في نفس الجلسة.
4. **الأرقام تُحدَّث بالأمر المذكور** في القسم 4 ثم يُحدَّث هذا الملف.
5. **أي مستند جديد في `docs/` يجب تسجيله في الجرد** (القسم 1) وإلا فشلت البوابة.
6. **لا توثيق «نوايا»:** يُوثَّق ما هو منفَّذ فعلاً في الكود. غير المنفَّذ يُكتب صراحة تحت «الفجوات المتبقية» في `docs/features-tracker.md`.

## 6. التحقق الآلي (Automated Enforcement)

```bash
# البوابة الكاملة (قبل الكومت) — تُشغَّل تلقائياً عبر frontend/.husky/pre-commit
node scripts/docs-gate.mjs

# قبل الدفع — تُشغَّل تلقائياً عبر frontend/.husky/pre-push
node scripts/docs-gate.mjs --push

# فحص صارم لكل مرجع مسار في AGENTS.md وقواعد ومهارات الوكلاء
node scripts/docs-gate.mjs --strict-refs

# تقرير الجودة الكمي (أرقام لا ادعاءات)
node scripts/quality-metrics.mjs

# تقرير تغطية Go (يقرأ coverprofile ناتج go test)
node scripts/coverage-gate.mjs --profile=coverage.out
```

**سلوك الأداة:** تخرج برمز `1` وفهرس عربي واضح عند أي انحراف يوقف الكومت، وتحذيرات غير معيقة للبنود التحذيرية.

**مفتاح الطوارئ:** `BEIDAR_DOCS_GATE=off` — يُستخدم فقط في حالة طارئة مبرَّرة، ويجب ذكر السبب في رسالة الكومت. الاستخدام المتكرر يُعد خرقاً للقاعدة الحاكمة.
